# Speech2Text V0.5 — Practical Daily-Use Offline Transcription

## Overview

Speech2Text V0.5 evolves the offline Android transcription application into a robust, practical daily-use tool. While preserving the frozen V0.4 primary screen and strict offline privacy guarantees (zero internet permissions, zero telemetry, zero cloud APIs), V0.5 adds full session lifecycle management:

1. **Inline Editable Transcripts** with real-time word counting and an "Edited" status badge.
2. **Immutable Original Preservation** with a dedicated view and restore workflow.
3. **Persistent Local Session History** stored completely on-device in app-private storage.
4. **Fast History Sheet** with date grouping ("Today", "Yesterday", specific dates) and real-time substring search.
5. **Session Management** including in-place renaming, run history details, and deletion.
6. **Alternate Engine Re-transcription** allowing users to re-run Moonshine Base or Zipformer across stored session audio with options to preserve or replace manual text edits.
7. **Reliable App Storage Organization** using atomic file writes and cached index summaries.

## 1. Storage & Directory Layout

All sessions reside inside the app's private internal storage (`context.filesDir`):

```text
files/
└── sessions/
    ├── index.json                  <-- Lightweight summary cache for fast list rendering
    └── <session-uuid>/
        ├── audio.wav               <-- Original 16,000 Hz, 16-bit mono PCM audio
        └── session.json            <-- Full metadata, edit state, and run history
```

### File Architecture Semantics
- **Atomic Writes**: `SessionRepository` writes JSON documents to a temporary file (`.tmp`) before atomic rename. On Windows/Android environments where `renameTo` requires target deletion, `SessionRepository` cleans the target first to prevent data corruption.
- **Independence from SAF Exports**: Deleting an internal session permanently removes its `sessions/<uuid>/` folder and updates `index.json`. It **never** touches or deletes documents previously exported to the user's `Music/Speech2Text` directory.
- **Unload vs Delete**:
  - *Clear current screen*: Unloads the session from active view, clearing the transcript and audio from memory. The session remains safe and untouched in History.
  - *Delete session*: Permanently removes the session, audio, and metadata from disk.

## 3. Core Capabilities & User Workflows

### 3.1 Inline Transcript Editing
- When a transcript is loaded, an **[Edit]** button appears in the header.
- Tapping **[Edit]** seamlessly switches the display to an inline `BasicTextField` styled to match the active application font (Segoe UI, Inter, Plus Jakarta Sans, JetBrains Mono, or System Default).
- The word count updates dynamically on every character change.
- Tapping **[Done]** commits the edit to the active session document and repository index, adding an **"Edited"** badge pill next to the word count.
- Tapping **[Cancel]** reverts unsaved keystrokes back to the previous text.

### 3.2 Original ASR Transcript Protection
- The raw speech recognition text is stored immutably in `original_transcript` and in the run history.
- If a transcript has been modified, an option **"View original transcription"** becomes active in the Advanced sheet under `FILE`.
- The dialog provides a read-only view of the raw model output, its original word count, and a confirmation-protected **"Restore Original"** button to revert manual changes.

### 3.3 Session History & Search
- Accessed via **Advanced → History** (`FILE → History`).
- Shows the total count of saved sessions (e.g. `Browse and reopen previous sessions (5 saved)`).
- Chronological grouping:
  - **Today**
  - **Yesterday**
  - **<Month> <Day>, <Year>**
- Real-time search filter: Matches query substrings against both session titles and transcript contents.
- Session Card details:
  - Title (default: `"Recording – yyyy-MM-dd HH:mm"` or `"Imported – <filename>"`).
  - Duration (`mm:ss`) and word count.
  - Model engine tag (Moonshine Base / Zipformer).
  - Timestamp.
  - "Edited" pill badge if manually edited.
- Session Action Menu (Three-dot dropdown):
  - **Open**: Reopens the session into the main screen, restoring audio, transcript, metrics, and session title.
  - **Rename**: Displays a rename dialog to customize the session title.
  - **Details**: Full diagnostic dialog displaying source type, duration, RTF, word count, inference time, manual edit status, and complete run history.
  - **Delete**: Prompts for confirmation and purges the session.

### 3.4 Alternate Engine Re-Transcription
- Accessed via **Advanced → Retranscribe session** (`TESTING → Retranscribe session`).
- Allows the user to select between **Moonshine Base** and **Zipformer** (with contextual technical hotword biasing).
- If manual text edits exist, the user is presented with a choice:
  - **Keep Edits**: Logs the new model recognition as an additional run in the session history while keeping the user's manual text intact.
  - **Replace**: Replaces the active transcript with the new recognition result and marks it unedited.
- The run history log persists all attempts with individual timestamps, inference durations, and RTF metrics.

## 4. Packaging & Model Assets Optimization

To ensure native Sherpa-ONNX C++ code (`libsherpa-onnx-jni.so`) can safely memory-map both ONNX models and text assets (tokens and hotword files) without encountering `SIGSEGV` null pointer dereferences from Android's `AAsset_getBuffer`, `app/build.gradle.kts` enforces zero deflation for all model and text files:

```kotlin
androidResources {
    // ONNX Runtime and sherpa-onnx memory-map model and text assets; they must not be deflated in the APK.
    noCompress += listOf("onnx", "ort", "txt")
}
```
